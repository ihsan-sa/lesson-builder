# Roadmap — accepted from the 2026-07-22 architecture review

Items from `codex-ultra-deep-review.md` (and the two audit rounds) that are agreed direction but deliberately NOT implemented as doc/prompt patches — each is a project needing a live harness or a product decision. Ordered by leverage. Immediate blockers from that review were fixed in-tree (see git log).

## P0 — runtime fixes that need the live sandbox first

Verify each against the running app (sandbox recipe: bootstrap fresh workspace → 17/17 → Playwright) before and after changing `Chatbot.jsx`:

1. ~~**Safe rendering for model output**~~ — landed 2026-09-05 (PR #5): DOMParser → allowlist → DOM nodes in `chat/safeRender.js`, no `innerHTML` on model output, CSP meta in the lesson template, 41-vector corpus under `tests/safe-render/`. (Chosen shape was markdown→string→allowlist-DOM rather than →React; same guarantees.)
2. ~~**Real cancellation**~~ — landed 2026-09-05 (PR #7): `POST /chat/cancel` owns the turn's process group, cancel wins over a clean exit, promotion only on completion, `tests/cancellation/`.
3. ~~**Suggestion approval stale closure**~~ — landed: the send path is routed through a ref (lessons #9 → PR #4), the rejection observation is emitted (`suggest-rejected`), and the approval carries the parsed JSX verbatim so the edit survives a resume or compaction.
4. ~~**Thread actors**~~ — landed 2026-09-05: a thread's first turn runs `--resume <main session> --fork-session`, so it takes its turn in a session of its own forked from the main conversation and nothing said in a thread enters the main history (a CLI that ignores the flag has that turn killed at its first line); `POST /thread/fold` summarizes the thread, the client shows the student that one summary and carries it into their next main turn, and that is the only route back. Stop is per thread, `/sessions` never offers a thread as a chat, and `tests/thread-actors/` probes all of it (fake CLI and real). The "reinforcement missing inside threads" half was stale — `<<REINFORCE>>` from a thread reply was already merged into the chat's list — and the orphaned `prompts/thread-system.md` that contradicted `buildSystemPrompt.js` is deleted.
5. ~~**Client resume metadata**~~ — landed 2026-09-05: `/session/open` echoes the session's stored `model`/`effort`, and `resumeSessionIntoTab` applies them (guarded against a model no longer in `MODELS`) so a resumed chat carries the settings it was created with instead of the client's current picks; `tests/resume-metadata/`.
6. ~~**KaTeX CDN resilience**~~ — landed 2026-09-05 (PR #6, and #8/#9 for Desmos): tri-state readiness with an 8 s bound, literal-source fallback, late loads recover; `tests/katex-fallback/`. Bundling KaTeX in core stays longer-term.

## P1 — reliability foundation

7. ~~**Run manifest**~~ — landed 2026-09-05: one versioned record per run at `<lesson_root>/.lesson-builder/runs/<run_id>.json` (schema `lesson-run/1`) holds scoping artifact, plan hash + approval, branch/base SHA, stash OID, media manifests with intents, and open findings; `scripts/run-manifest.cjs` is the only reader and writer, `lesson_build.log.md` is rendered from the records (a log written before them is kept above the render marker), and the phase docs read every field from the record instead of the markdown. The headless approval gate now decides on `plan.hash` alone, with the approved-but-nothing-recorded case an explicit refusal (exit 4) rather than a silent proceed; schema and gate outcomes in `references/run-record.md`, fixture in `tests/run-manifest/`. Still open for `consolidate`: the per-lesson change-lists and the completed/remaining lists a partially-run restructure leaves behind.
8. ~~**Worktree-per-run**~~ — landed 2026-09-05: an update builds in a git worktree of its own at `<lesson_root>/.lesson-builder/worktrees/<run_id>/`, checked out from the base SHA Phase 0 records, so the user's working tree is byte-identical from Phase 0 to the end of Phase 5 — nothing is stashed, no branch is switched, nothing is written into their checkout. Phase 5 commits and merges `--no-ff` in there too, on a detached HEAD, and moves `refs/heads/<base>` only when no working tree has it checked out (git refuses to push or fetch into a checked-out branch for the same reason); otherwise it pushes the merge and reports the one fast-forward the user runs. `worktree add` leaves a pointer so a run inside the worktree still finds its record, and `worktree remove` refuses while the worktree holds work no ref keeps — the rollback invariant in code. `git.stash_oid`/`_ref`/`_branch` are legacy: recovery reads them, `set` refuses to write them, and `references/update-mode.md` § Recovering a run from the old stash flow finishes or rolls back a run left mid-update by the old flow. Fixture in `tests/worktree-per-run/`.
9. ~~**Stage-then-promote for every producer**~~ — landed 2026-09-05: every producer writes into the run staging area (`.lesson-builder/staging/<run_id>/<media_id>/`, printed by `run-manifest.cjs stage`), and an artifact enters the lesson tree only through `run-manifest.cjs promote`, which refuses anything this run did not stage, checks the staged bytes are a complete file of their kind (PNG `IEND`, JPEG `EOI`, MP4 boxes that tile the file, UTF-8 sources), records its SHA-256 on the media row, and lands it by write-to-`.part`-then-rename — so the final name never holds a partial file. Identical bytes are left alone entirely; a refusal or `fail` records the reason and leaves the previous artifact untouched. manim-runner renders into staging and keeps every stage it had; matplotlib figures and sources, web images and manim sources stopped writing into `public/` and `figures/`; the media-id-to-path convention is owned by `references/phase-3-execution.md` § The run staging area instead of being repeated in each agent doc. Schema and exit codes in `references/run-record.md` § Artifacts, fixture in `tests/stage-promote/` (node only — no manim, ffmpeg, browser or network).
10. ~~**Attestation-cached no-grandfathering**~~ — landed 2026-09-05: a Phase 4 verdict is recorded on its media row with what it attests to — the artifact's bytes, the rubric that judged it by its own bytes, the reviewer and its model, and every dependency the review declares — and a later run reuses it instead of re-reviewing an artifact nothing has touched. Coverage is preserved by proof, never by omission: an artifact with no valid attestation is reviewed, and `run-manifest.cjs attest verify` refuses the handoff to Phase 5 (exit 8) while any review the run's spec asks for lacks a valid verdict in that run's record. A ref is a lesson-relative path, `skill:<path>` for one of the skill's own files (a rubric, a reviewer prompt — so a record holds no path that is only true on one machine), or `<file>#<Name>` for one top-level declaration or demo inside a file, hashed by the new `lesson-ast.cjs digest`: that last form is what lets a verdict attest to one graph in a shared lesson file, so refining one graph does not invalidate the five beside it. An attestation is invalid the moment any ref hashes differently, is gone, or is not in the review any more, or the reviewer's model changed; bytes are re-hashed from disk, so an artifact edited without its record being updated is never reused, and a record written before this existed reuses nothing. The `--spec` file is the one declaration of what each review depends on, so what was checked and what was attested cannot drift; the fix loop's widening rule is the same relation it declares. The no-grandfathering rule keeps its meaning — every medium still ends the run with a verdict from its full team — and reuse is visible in the rendered log as `REUSED from run <id>`. Schema and commands in `references/run-record.md` § Attested verdicts, procedure in `references/phase-4-review.md` § Reusing a verdict that still holds, fixture in `tests/attestation/`.
11. ~~**AST-based inventory + splice**~~ — landed 2026-09-05: `scripts/lesson-ast.cjs` Babel-parses the lesson, and the Phase 1 inventory, the Phase 3 splice and the decision that something is unused all read that tree. `inventory` replaces the nine grep and glob steps and prints the same documented dict, with three derivations fixed: a graph component is the `({ params, mid })` signature rather than a capital letter, so a lesson-local `HWQuestion` is a helper and not a graph; a manim source is paired to its video on named evidence (matching stems, a `class <Name>` that normalises to the video's stem, or the filename in the source text) instead of a trusted stem, so a source manim named after its Scene is no longer an orphan; and `state_hooks`, line ranges and the `DEFAULT_GRAPH_PARAMS` key each component reads come from the tree. `replace` and `remove` rewrite a named node's own byte range — component, call site, constant, demo, params key, schema key — so nothing counts braces, a target that matches nothing exits 3 and a result that would not parse exits 4, both writing nothing; each `--write` prints a receipt naming what it replaced and reporting every top-level declaration no target named as re-parsed and byte-identical (a splice that would have changed one exits 4 instead), which retires the ±25% line-count delta check. `reachability` reports what a removal strands, transitively, and is what § 4.4 and the splice checklist now run. The inventory's schema keeps its meaning — `orphans` is still files on disk that Phase 3 § 4.9 may delete — and the new `lesson_helpers` field is where an unused in-file helper is reported. A lesson the parser cannot read halts with the parse error and never falls back to regex. Fixture in `tests/ast-inventory/`.

## P2 — product shape (user decisions)

12. **Lesson shell monorepo** — lessons become manifest + topic/media modules mounted in one shared app shell; one lockfile; generated registry (replaces hand-edited `build-all.sh` inventory). Migrate legacy single-file lessons only on material update, via codemod.
13. **Tutor / authoring-copilot split** — student tutor: read-only tools, typed graph actions, deployable backend; authoring copilot: local-only, capability escalation, patch-sandbox mutation with rendered diff approval. Today's union-of-capabilities prompt+proxy serves both and over-privileges every turn.
14. **Typed action channel** — replace the seven `<<TAG>>` regex protocols with versioned JSON actions validated server-side, dispatched exactly once post-completion; legacy tags parsed only during migration.
15. **`defineGraph`** — single typed declaration generating `DEFAULT_GRAPH_PARAMS`, `GRAPH_SCHEMA`, validation, and prompt metadata (removes the manual key-parity invariant + backfill machinery).
16. **Eval suites as release gates** — builder fixture bank (interrupted/resumed runs, dirty trees, capability-missing fallbacks, branch collisions, malformed agent returns) graded on environment outcomes; multi-turn tutor evals (hint-ladder compliance, insistence, injection resistance, thread isolation); runtime contract tests (SSE byte-split fuzz, route-manifest parity, XSS corpus, component-example rendering). skill-creator plugin can host the description/trigger evals.

## Teaching-quality eval (from the 2026-08 teaching spec, Stage 5)

17. **Stage 5 teaching eval** — tutor half: the 100 stratified cases in `evals/teaching/tutor-cases.jsonl` run blind pairwise (old vs. new prompt, order randomized) and judged per `evals/teaching/rubric.md` Part B with rubric-tied reasons, broken down by mode and attribute (case file authored 2026-08-15; the run is cost-bearing and on request). Lesson half: 6–10 generated topics across knowledge types with delayed recall and near/far transfer — needs real builds and human learners. Success criterion is unaided learning and transfer, never assisted performance or satisfaction; average length is not a metric. Reversal conditions live in `references/teaching-communication.md` § Guardrails. Stages 1 and 4 (tutor probes; 24 blind fixtures) are runnable now and were run at landing; Stage 2 (generated-lesson exposition checks) needs real builds; Stage 3's reorder-test rejection is recorded in `evals/teaching/plan-rejection-case.md` pending a live-run instance.

## Explicitly rejected / kept as-is

- Bearer-token auth on the proxy: loopback bind + CORS + argv allowlists cover the local threat model; tokens add Vite plumbing for little gain until the copilot split (#13).
- Removing the Phase 5 build under `deploy_action: skip`: deliberate — the user learns whether the lesson builds.
- Retiring `code-review-agent` from the build gate: its grep+judgment layer stays until `lesson-lint` (#16) exists.
